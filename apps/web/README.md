# Фронтенд `@canvas/web`

Список пространств и канвас на React Flow: ноды «Текст», «Генератор», «Результат», связи между портами, автосохранение графа с `If-Match`, запуск тестовой генерации и картинка в ноде результата. Идентификатор пространства живёт в адресе страницы, `localStorage` не используется.

## Запуск

Node.js 24, npm 11, команды из корня репозитория.

```sh
npm ci                # зависимости всего workspace
npm run dev           # API на http://localhost:4001
npm run dev:web       # фронтенд на http://localhost:5173, во втором терминале
```

```sh
npm run build:web                  # контракты и фронтенд в apps/web/dist
npm run preview -w @canvas/web     # собранный фронтенд
npm run check:web                  # lint, typecheck, тесты фронтенда
npm run check                      # плюс форматирование, бэкенд и OpenAPI
```

Адрес API в `VITE_API_URL` (`apps/web/.env.example`), по умолчанию `http://localhost:4001`.

## Стек

Vite 8, React 19 с React Compiler, TypeScript strict, react-router 8, TanStack Query 5, axios, `@xyflow/react` 12, zustand 5, Tailwind CSS 4, примитивы shadcn на Radix, Vitest, Testing Library, msw. React Flow приносит с собой zustand 4, стор графа написан на пятой версии, в бандле обе.

## Слой API

Все запросы идут через `src/shared/api`. Дальше него `Response`, `AxiosError`, `response.ok` и `response.json()` не встречаются: хуки получают данные или `ApiError`.

| Файл                         | Что делает                                                                                                                                                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `client.ts`                  | Экземпляр axios: базовый адрес, таймаут, `Accept`, `Content-Type: application/json` для `POST` и `PUT`.                                                                                                                 |
| `request.ts`                 | `request<T>(endpoint)` отдаёт тело, `requestWithMeta<T>(endpoint)` отдаёт `{ data, etag, location }`. Описание запроса: метод, путь, тело, `ifMatch`, `idempotencyKey`.                                                 |
| `envelope.ts`                | Разбор ответа: тело и есть ресурс, `204` даёт `undefined`, не-JSON тело даёт ошибку разбора; `ETag` и `Location` читаются из заголовков здесь и больше нигде.                                                           |
| `error.ts`                   | `ApiError` с `kind` (`network`, `http`, `parse`), `code`, `status`, `message`, `requestId`; сетевая, HTTP и parse-ошибка приводятся к нему в одном месте.                                                               |
| `query-client.ts`            | `QueryClient`: повтор только сетевых ошибок, без перезапроса при фокусе окна, ошибка хуков типизирована как `ApiError`.                                                                                                 |
| `use-idempotent-mutation.ts` | Ключ идемпотентности для запуска генерации.                                                                                                                                                                             |
| `polling.ts`                 | Опции опроса для `useQuery`: пока данные в обработке, до результата или ошибки API; при сетевых сбоях опрос продолжается, но останавливается после десяти интервалов без ответа сервера, остановка при размонтировании. |

Новый запрос это одна функция рядом с сущностью, например в `entities/graph/api/graph.api.ts`:

```ts
export const putGraph = (spaceId: string, json: string, ifMatch: string) =>
  requestWithMeta<GraphData>({ method: 'PUT', path: graphPath(spaceId), body: json, ifMatch }).then(
    versioned,
  );
```

Тело графа уходит уже готовой строкой: сервер считает `ETag` от байтов, и повтор тех же байт даёт тот же `ETag`.

Ключ идемпотентности живёт в `useIdempotentMutation`. Пока предыдущая попытка не получила ответа сервера и тело совпадает, ключ тот же; любой ответ сервера закрывает попытку, следующий вызов получает новый UUID. В тело запуска входит `graphETag`, поэтому повтор после обрыва сети отправляет тот же ключ и то же тело, а запуск после правки графа получает новый ключ.

## Debounce и очередь сохранений

Очередь в `src/shared/lib/serial-saver.ts` ничего не знает ни о графе, ни о HTTP: ей отдают снимок и функцию сохранения.

- `schedule(snapshot)` запоминает последний снимок и перезапускает таймер на 500 мс; серия правок даёт один запрос, одиночная правка тоже сохраняется.
- Пока запрос в полёте, новые снимки копятся и уходят одним следующим запросом после ответа: запросы одного графа строго последовательны, и каждый следующий берёт `ETag` из ответа предыдущего.
- `flush()` отправляет несохранённое сразу, дожидается всего хвоста очереди и отдаёт результат последнего сохранения. Кнопка генерации вызывает `flush()` и запускает генерацию только с полученным `ETag`; при ошибке сохранения запуска нет.
- Ошибка переводит очередь в `error`, снимок остаётся, статус в шапке показывает текст ошибки и «Повторить». Перед повтором стор читает граф с сервера: если ответ на прошлый `PUT` потерялся, а правка дошла, серверная версия совпадёт со снимком, и стор просто берёт её `ETag` без повторного `PUT`; иначе отправляет снимок заново. Ответ `412` переводит в `halted`: автосохранение стоит, черновик остаётся на канвасе, полоса под шапкой предлагает загрузить версию с сервера или заменить её своей (свежий `ETag` через `GET`, затем `flush()`).

Стор графа (`entities/graph/model/graph.store.ts`) на zustand держит ноды и рёбра React Flow как есть, `viewport`, `ETag` и индексы. Сохранение запускают изменения типов `add`, `remove`, `replace`, `position`, ввод текста, связи и конец движения канваса; выделение и измерение размеров ноды его не трогают. Перед отправкой снимок проецируется в контракт (`toGraph`: у нод остаются `id`, `type`, `position`, `data`, у рёбер `id`, `source`, `target`), сериализуется и сравнивается с последней отправленной строкой: одинаковый граф второй раз не уходит.

Генерации: один список `GET /generations` в TanStack Query с опросом раз в 500 мс, пока в нём есть `processing`. Из списка за один проход строятся две карты: последняя попытка по генератору и по ноде результата. Результат показывается, только если попытка по ноде результата совпадает с последней попыткой её генератора, поэтому старый результат не попадает в переподключённую ноду и не перекрывает более новую попытку. После перезагрузки список читается заново и незавершённая генерация продолжает опрашиваться. Сетевой сбой опрос не прерывает; если сервер не отвечает десять интервалов подряд, опрос останавливается, генератор показывает текст ошибки и «Повторить».

## Обработка данных

Самый частый участок: индексы графа в `entities/graph/model/graph-rules.ts`.

```ts
export const indexGraph = (nodes, edges) => {
  const nodeById = new Map();
  for (const node of nodes) nodeById.set(node.id, node);
  const sourceOfInput = new Map();
  const targetOfGenerator = new Map();
  for (const edge of edges) {
    sourceOfInput.set(edge.target, edge.source);
    if (nodeById.get(edge.source)?.type === 'generator')
      targetOfGenerator.set(edge.source, edge.target);
  }
  return { nodeById, sourceOfInput, targetOfGenerator };
};
```

Индекс пересчитывается в действии стора вместе с нодами и рёбрами: при добавлении, удалении и соединении. Ввод текста заменяет одну запись в `nodeById`, карты связей остаются прежними. Перемещение ноды, выделение и измерение размеров индекс не трогают: правила читают тип ноды, текст и связи, координаты им не нужны. Один проход по нодам и один по рёбрам, три `Map` с записью на элемент, без промежуточных массивов.

Читают индекс два горячих места. `isValidConnection` вызывается на каждое движение мыши при протяжке связи: `canConnect` делает четыре обращения к `Map` по ключу, без обхода массивов. `completeChain` перед запуском генерации находит текст и результат генератора двумя обращениями. Кнопка «Соединить выбранные» проверяет пару выделенных нод той же функцией в обе стороны.

Индекс генераций строится в `select` запроса списка: одна функция на модуль, TanStack Query не вызывает её заново, пока ссылка на список не изменилась. Ноды подписаны на стор селекторами и перерисовываются только при смене своих полей. Единственный `useMemo` в коде стоит в `SpaceCanvas`: рёбра с флагом `animated` пересобираются только при смене рёбер или набора обрабатываемых генераторов, иначе React Flow получал бы новый массив на каждом опросе.

## Проверено

71 тест в `npm run check:web`, HTTP мокируется через msw.

- Слой API: тело без обёртки, `204`, `ETag` и `Location`, три вида ошибок, `If-Match` и `Idempotency-Key`, строка тела байт в байт, правило ключа идемпотентности, повтор только сетевых ошибок, опрос до результата и его остановка при размонтировании, ошибке API и после десяти интервалов сетевых сбоев.
- Очередь сохранений: серия правок даёт одно сохранение, одиночная тоже; правки во время запроса ждут его и уходят одним запросом; `flush` отправляет сразу, ждёт хвост очереди и отдаёт результат; ошибка сохраняет снимок для повтора; останавливающая ошибка выключает автосохранение до `resume`.
- Стор графа: перемещение сохраняется после паузы и обновляет `ETag`; после потерянного ответа повтор сверяется с сервером и не шлёт `PUT`, если правка дошла; ввод текста обновляет одну запись индекса; выделение и измерение не сохраняют; одинаковый граф не отправляется повторно; ввод текста меняет только свою ноду; удаление убирает связи и индексы; новая связь получает UUID; лимит 20 нод; viewport сохраняется; `flush` без правок отдаёт текущий `ETag`; конфликт останавливает сохранение, запись своей версии берёт свежий `ETag`; имена нод и рёбер для чтения с экрана; соединение двух выделенных нод в любом порядке, несовместимая пара не соединяется.
- Правила и проекция: только «текст → генератор» и «генератор → результат», один вход, один выход у генератора, текст питает несколько генераторов; полная цепочка требует непустой текст; `toGraph` оставляет только поля контракта, служебные поля не влияют на строку сохранения.
- Генерации: последняя попытка по генератору и по результату, результат только для последней попытки своего генератора, отказ и обработка без результата, опрос пока есть `processing`.
- Страницы: список пространств со ссылками, пустое состояние, ошибка с повтором, пустое название не отправляется, после создания открывается канвас; страница канваса показывает загрузку, 404 со ссылкой на список и ошибку сервера с повтором.

Руками в Chrome на 1280 px: создание пространства и восстановление после перезагрузки; добавление, перемещение и удаление нод кнопкой и клавишами Enter, Delete; связи протяжкой и через «Соединить выбранные», недопустимая связь отклоняется; один `PUT` на серию правок; конфликт `412` при правке извне, загрузка серверной версии и замена своей; генерация успех с картинкой, отказ с повтором, перезагрузка во время обработки с продолжением опроса (проверено с задержкой сервера 6 с); фокус с клавиатуры, русские имена нод и контролов в дереве доступности. На 390 px шапка переносится, горизонтальной прокрутки нет. `npm run smoke` проходит.

## Решения

- Vite: приложение клиентское, состояние живёт на сервере и в адресе страницы, серверный рендер ничего бы не добавил.
- zustand для графа: React Flow советует внешний стор для канваса, очередь сохранения и индексы лежат рядом с нодами. TanStack Query для серверного состояния, включая список генераций.
- Стор пересоздаётся провайдером с ключом по `ETag` загрузки: «Загрузить версию с сервера» это обычный `refetch`, без ручной синхронизации состояний.
- Данные генераций не пишутся в `data` нод: сервер принимает только поля контракта, а результат определяется по картам из списка генераций.
- Интервалы и лимиты константы (`shared/config/limits.ts`): debounce 500 мс задан заданием, лимит 20 нод в контрактах, опрос 500 мс как `pollIntervalMs` в `/api/config`.
- Сценарий отказа выбирается чипами в ноде генератора и не сохраняется: в `data` генератора по контракту только `label`.
- Ключи описания ноды в `ariaLabelConfig` React Flow 12.11 перепутаны в самой библиотеке: текст подсказки положен под `keyboardDisabled`, чтобы читаться при включённой клавиатуре.
- При уходе со страницы канваса провайдер стора вызывает `flush()`, несохранённые правки доходят до сервера.

## Не сделано

- Соединение портов протяжкой доступно только мышью, это ограничение React Flow; для клавиатуры есть действие «Соединить выбранные».
- Атрибуция React Flow в углу канваса оставлена: авторы библиотеки просят не скрывать её без Pro-подписки.
- Ключ идемпотентности запуска генерации живёт в памяти вкладки. Если перезагрузить страницу, пока ответ на запуск не пришёл, повтор уйдёт с новым ключом; созданная попытка при этом видна в списке генераций после загрузки.
- При конфликте нет слияния версий, только выбор одной из двух.
- `Retry-After` из ответа `202` не читается, опрос идёт с шагом 500 мс: у генераций, восстановленных после перезагрузки из списка, этого заголовка нет. Шаг не растёт при сбоях; вместо этого опрос останавливается после десяти шагов без ответа сервера.
- End-to-end тестов в браузере нет, канвас проверен руками.
